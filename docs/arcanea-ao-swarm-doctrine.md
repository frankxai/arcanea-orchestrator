# Arcanea/AO Swarm Doctrine

AO is the Arcanea execution and orchestration lane. It turns intent into routed work, tracks agent sessions, keeps ownership visible, and moves tasks through queues, handoffs, review loops, and recovery paths. AO should stay operational: it coordinates work across agents and repositories, but it is not the place where Arcanea canon is invented by accident.

Arcanea-specific swarms are the creative and continuity lanes. They specialize in worldbuilding, fictional stories, canon stewardship, Arcanea World, multiverse structure, media systems, character continuity, lore portability, and franchise-facing assets. Their outputs can become AO tasks when execution is needed, but their authority is domain-specific: they protect the imaginative system, story logic, and canon boundaries.

## Operating Model

- **Starlight Queen** is the sovereign routing and priority layer. It sets strategic direction, resolves high-level tradeoffs, and decides which lane should own ambiguous work.
- **SO** is the Starlight operations layer. It turns strategic intent into operational motion across repos, releases, products, dashboards, docs, and coordination rituals.
- **SIS** is the intelligence and memory layer. It preserves context, decisions, reusable doctrine, evidence, and handoff state so agents do not repeatedly rediscover the same facts.
- **AO** is the execution lane for agent orchestration. It manages sessions, queues, worktree isolation, status, escalation, and delivery mechanics.
- **Arcanea swarms** are specialist creative systems. They should be invoked when work touches canon, worlds, narratives, mythology, media formats, multiverse architecture, or Arcanea-specific product imagination.

## Queue-Driven Agents

The default agent model is queue-driven. Work enters as a scoped prompt, issue, task, or handoff package; AO assigns it to an agent session; the session reports status, asks for escalation when blocked, and returns artifacts. Queues keep swarm work inspectable: every unit should have an owner, a current state, a next action, and enough context for replacement or recovery.

Arcanea swarms should also use queues, but with creative gates. A canon-sensitive task should declare whether it is exploratory, draft, candidate canon, or canon-locked. AO can move the work, spawn agents, and preserve evidence, while the Arcanea swarm decides whether the creative output is valid for the world.

## Routing Rule

Use AO when the question is "how do we execute, coordinate, recover, or ship this?"

Use an Arcanea-specific swarm when the question is "what is true, coherent, beautiful, or permissible inside Arcanea?"

Use SIS when the question is "what do we already know, what did we decide, and what context must persist?"

Use SO when the question is "what operating motion, cadence, or cross-system coordination should happen next?"

Use Starlight Queen when ownership, priority, or doctrine conflicts across lanes.

## Doctrine

AO should not collapse all swarm identity into one generic orchestrator. It is the execution spine for Arcanea work, not the creative authority for Arcanea itself. Arcanea swarms should not become free-floating creative chats; they should produce structured outputs that AO can queue, track, review, and hand off.

The healthy pattern is separation with exchange: Starlight Queen sets direction, SO operationalizes, SIS remembers, AO orchestrates execution, and Arcanea swarms protect the worlds.
